# Horoi v1.1 Release Candidate Gate

This archive is a hardened release candidate, not a claim that runtime verification occurred inside the packaging environment.

## Source-level fixes included

- Official BEP-677 optional interface IDs corrected.
- `IERC8056Scheduled` discovery added.
- Chain ID is validated even with a custom RPC URL.
- Pinned block timestamp drives pending-state checks.
- H005 decodes the real `TransferWithUIAmount` receipt log.
- H007/H008 execute optional conversion/balance calls when supported.
- Fork users are funded from an actual holder; no token storage mutation.
- Multiplier updater is discovered through `owner()` or historical update sender.
- Forward split, reverse split, and dividend scenarios use independent fork snapshots.
- Raw BEP-20 accounting stays canonical; effective amount is derived once.
- H109 uses real two-user proportionality evidence.
- H110 attempts a real small deposit/redeem boundary.
- All large integer comparisons remain `bigint`.
- Evidence is bound into `resultHash`; runtime `runId` is excluded from semantic hashing.
- Generic custody no longer fakes redemption and therefore cannot yield a full PASS.
- Registry revocation is admin-only; one publisher cannot revoke another publisher's report.
- HTTP run execution is asynchronous with progress and restart recovery.
- Old NVDAB report JSON generated by the pre-v1.1 engine was removed.

## External/runtime blockers the maintainer must finish

1. Install Bun/Foundry dependencies and run the exact release commands below.
2. Supply a reliable BSC mainnet RPC.
3. Supply a real ERC-4626-like target that actually accepts the selected bStock; otherwise integration checks remain INCOMPLETE by design.
4. If automatic holder discovery is rate-limited, provide `--holder 0x...` or `HOROI_HOLDER_ADDRESS` for a funded holder at the pinned block.
5. Deploy `HoroiRegistry` on BSC mainnet with the maintainer wallet and BNB, verify source, then publish one fresh report.
6. Record <=4 minute demo and complete the portal submission.

## Exact verification commands

```bash
bun install --frozen-lockfile
bun run typecheck
bun run test
forge fmt --check
forge build
forge test
bun run --cwd frontend build
```

Then:

```bash
export BSC_RPC_URL=<reliable BSC mainnet RPC>
NVDAB=0x02Fca66C1D1aFB4E2A7884261eB00F63598a7436
bun backend/cli.ts inspect $NVDAB --json
bun backend/cli.ts test $NVDAB <REAL_TARGET> --profile erc4626 --holder <FUNDED_HOLDER> --json
```

Do not publish a PASS unless every required check actually executes and passes. INCOMPLETE is the correct result when an updater, holder, target, or faithful transition is unavailable.
