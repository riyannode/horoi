# Horoi v1.2 Integration Conformance Release Candidate Gate

Repository: https://github.com/riyannode/horoi

This archive is a hardened release candidate. Local verification and the pinned NVDAB archive/fork evidence are recorded in [docs/TESTS.md](TESTS.md). The archive provider credential is not stored in this repository.

## Source-level fixes included

- Official BEP-677 optional interface IDs corrected.
- `IERC8056Scheduled` discovery added.
- Chain ID is validated even with a custom RPC URL.
- Pinned block timestamp drives pending-state checks.
- H005 decodes the real `TransferWithUIAmount` receipt log.
- H007/H008 execute optional conversion/balance calls when supported.
- Fork users are funded from an actual holder; no token storage mutation.
- Multiplier updater is discovered through `owner()` or historical update sender.
- Forward split, reverse split, and dividend scenarios use independent fork snapshots.
- Raw BEP-20 accounting stays canonical; effective amount is derived once.
- H109 uses real two-user proportionality evidence.
- H110 attempts a real small deposit/redeem boundary.
- All large integer comparisons remain `bigint`.
- Evidence is bound into `resultHash`; runtime `runId` is excluded from semantic hashing.
- Generic custody no longer fakes redemption and therefore cannot yield a full PASS.
- Transparent `HoroiVault` harness added with raw canonical accounting, proportional multi-user claims, redeem/withdraw, and fractional boundary coverage.
- Explicit `TEST/INCOMPATIBLE` `NaiveHoroiVault` fixture proves stale effective-unit accounting yields deterministic `FAIL`.
- Adapter boundary now includes `expectedClaim`; adapters expose actions/state only and the engine remains the sole verdict source.
- NVDAB updater discovery checks enumerable `DEFAULT_ADMIN_ROLE`; H006 verifies the authorized forward 2.0x scheduled transition, while H104 and H105 verify the compatible reverse 0.1x and dividend-like 1.008x scenarios.
- Canonical result hashing excludes run/runtime/context noise; normalized Binance context is hashed separately.
- Exact HoroiRegistry calldata and Binance Transaction API simulation payload hashing are persisted with stale-payload protection.
- Registry revocation is admin-only; one publisher cannot revoke another publisher's report.
- HTTP run execution is asynchronous with progress and restart recovery.
- Old NVDAB report JSON generated by the pre-v1.1 engine was removed.

## Pinned-fork smoke reproduction

The transparent `HoroiVault` harness is the reproducible v1 integration target.
External third-party protocol conformance is an optional validation target, not a
v1 release blocker. Run the compatible fixture first; its H101-H110 report must pass
before running the expected-failing incompatible fixture:

```bash
forge build

BSC_RPC_URL="$BSC_ARCHIVE_RPC_URL" \
HOROI_SMOKE_FIXTURE=compatible \
bun run smoke:fork

BSC_RPC_URL="$BSC_ARCHIVE_RPC_URL" \
HOROI_SMOKE_FIXTURE=incompatible \
bun run smoke:fork
```

The runtime evidence and expected fixture outcomes are recorded in
[docs/TESTS.md](TESTS.md). Supply the archive RPC through the local environment; do not
store its endpoint or credential in this repository.

## Optional example for future third-party integrations

The following CLI example is optional and illustrates a future external-target
validation. It is not required for the v1 harness conformance proof:

```bash
export BSC_RPC_URL=<reliable BSC mainnet RPC>
NVDAB=0x02Fca66C1D1aFB4E2A7884261eB00F63598a7436
bun backend/cli.ts inspect $NVDAB --json
bun backend/cli.ts test $NVDAB <REAL_TARGET> --profile erc4626 --holder <FUNDED_HOLDER> --json
```

Do not publish a PASS unless every required check actually executes and passes. INCOMPLETE is the correct result when an updater, holder, target, or faithful transition is unavailable.
